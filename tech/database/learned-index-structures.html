🧠 Learned Index Structures

Thay thế B-Tree bằng Machine Learning model — RM-Index, CDF prediction, p = F(Key)×N, so sánh với B-Tree trên read-only workloads (Google / MIT, 2017)

1. Ý Tưởng Đột Phá: Index Như Một Function

Bài báo "The Case for Learned Index Structures" (Kraska et al., Google/MIT, 2017) đặt ra câu hỏi táo bạo: tại sao chúng ta lại dùng B-Tree — một cấu trúc dữ liệu tổng quát — làm index, trong khi index chỉ cần thực hiện một nhiệm vụ duy nhất?

💡 Index Là Gì? — Định Nghĩa Toán Học

Index về bản chất là một function: f(key) → position. Cho một key, trả về vị trí (offset) của record trong data file. B-Tree là một cách tổng quát để implement function này — nó hoạt động với mọi distribution dữ liệu. Nhưng nếu chúng ta biết distribution trước, ta có thể dùng model tinh chỉnh hơn và nhanh hơn nhiều.

Cụ thể hơn: B-Tree Range Index implement function f(key) → sorted_position. Nếu data được sorted theo key, position = CDF(key) × N, trong đó CDF(key) là Cumulative Distribution Function của key distribution và N là tổng số records. Nếu chúng ta có thể học CDF của data, chúng ta có thể thay thế B-Tree bằng một ML model.

2. Công Thức Cốt Lõi: p = F(Key) × N

Giả sử ta có N records được sort theo key. Record thứ i có rank i trong sorted order. CDF của key distribution cho biết: với key K, bao nhiêu % keys trong dataset nhỏ hơn hoặc bằng K.

-- Công thức cơ bản:
position = F(key) × N

-- Trong đó:
-- F(key) = CDF của key distribution, giá trị trong [0, 1]
-- N = tổng số records
-- position = predicted index position (offset trong sorted data)

-- Ví dụ:
-- Dataset: 1,000,000 user IDs được sort (1 đến 1,000,000)
-- Key = 500,000
-- F(500,000) ≈ 0.5 (nếu uniform distribution)
-- position = 0.5 × 1,000,000 = 500,000 ✓ (chính xác!)

-- Với non-uniform distribution (e.g., Zipf):
-- F(key) phức tạp hơn → cần ML model để học
-- Nhưng vẫn O(1) inference nếu model đủ nhỏ

2.1 Tại Sao ML Có Thể Học CDF?

CDF là hàm monotonically increasing (không giảm) — tính chất này rất thuận lợi cho ML. Neural network với activation functions monotone (ReLU) tự nhiên học được CDF. Thậm chí linear regression đơn giản cũng có thể approximate CDF của nhiều distribution thực tế (uniform, Gaussian, log-normal).

3. RM-Index: Recursive Model Index

Một model đơn lẻ không đủ chính xác cho dataset lớn với complex distribution. Bài báo đề xuất Recursive Model Index (RM-Index) — một hierarchy của models, tương tự B-Tree hierarchy nhưng thay node bằng ML model.

3.1 Kiến Trúc RM-Index

Stage 0: Root Model (1 model)
Neural network lớn (e.g., 2 hidden layers, 32 units). Predict approximate position với accuracy thấp nhưng biết "region" nào trong data. Output: index của model ở Stage 1 nên dùng.
→ Output range [0, M1-1] chọn 1 trong M1 Stage-1 models
Stage 1: Intermediate Models (M1 models)
Mỗi model phụ trách một region nhỏ hơn của key space. Thường là linear regression hoặc small NN. Accuracy cao hơn Stage 0 cho sub-range của mình.
→ Output range [0, M2-1] chọn 1 trong M2 Stage-2 models
Stage L: Leaf Models (ML models)
Models nhỏ nhất, phụ trách range nhỏ nhất. Thường là linear regression 2-parameter. Predict position trong range [pos_min, pos_max] với error nhỏ. Error bound được pre-computed.
→ Output: predicted_position ± max_error → scan trong range này
👉 [CHÈN ẢNH: RM-Index hierarchy — 1 root NN → M1 intermediate models → M2 leaf linear models → data, với key path highlighted]

3.2 Lookup Algorithm

def lookup(key, target_value):
    # Stage 0: Root model
    model_idx = root_model.predict(key)

    # Stage 1...L-1: Intermediate models
    for stage in range(1, L-1):
        model_idx = stage_models[stage][model_idx].predict(key)

    # Stage L: Leaf model
    predicted_pos = leaf_models[model_idx].predict(key)

    # Bound the prediction error
    min_pos = max(0, predicted_pos - max_error[model_idx])
    max_pos = min(N-1, predicted_pos + max_error[model_idx])

    # Last mile: binary search or linear scan in [min_pos, max_pos]
    # max_error thường nhỏ (vài trăm records) → very fast
    return binary_search(data[min_pos:max_pos], key, target_value)

3.3 Training Process

RM-Index được train offline khi data đã được sorted:

  1. Stage 0 training: Train root model trên toàn bộ dataset. Input: key, Label: position/N (0..1). Optimize với Adam/SGD.
  2. Stage 1 training: Với mỗi Stage-1 model m, collect keys mà Stage-0 predicts rơi vào bucket m. Train model m trên subset đó.
  3. Leaf model training: Tương tự, nhưng dùng linear regression. Compute max_error cho mỗi leaf model.
  4. Error bound computation: Với mỗi leaf model, tìm max absolute error trên training set → đây là guaranteed search range.

⚠️ Chỉ Dùng Được Với Read-Only Data

RM-Index như được mô tả trong bài báo gốc chỉ hoạt động với static, read-only data. Khi data thay đổi (inserts/updates/deletes), cả model hierarchy phải được retrain. Đây là limitation lớn nhất — database workloads thực tế thường có writes. Các nghiên cứu tiếp theo (Alex, PGM-Index) giải quyết vấn đề này nhưng phức tạp hơn nhiều.

5. Các Index Type Khác Được "Learned"

Bài báo không chỉ dừng ở range index. Các tác giả đề xuất learned versions cho 3 loại index chính:

5.1 Learned Hash Index

Hash index thông thường dùng hash function tổng quát (e.g., MurmurHash). Nhưng nếu key distribution được biết trước, một "learned hash function" có thể tối thiểu hóa collisions cho distribution đó cụ thể — không cần xử lý collision nhiều như hash table tổng quát.

// B-Tree Range Index: learned CDF model
position = F(key) × N  ± max_error

// Learned Hash Index: reduce collision
bucket = learned_hash(key) % M
// learned_hash minimize collision rate for known distribution

// Learned Bloom Filter: reduce false positive rate
// Thay vì k hash functions cố định:
p_exists = neural_network.predict(key)
if p_exists > threshold: return EXISTS (may false positive)
else: return NOT_EXISTS (no false negative guaranteed)

5.2 Learned Bloom Filter

Bloom Filter thông thường không biết gì về semantics của key — mọi key đều xử lý như nhau. Learned Bloom Filter dùng ML model để distinguish "likely to exist" vs "likely not to exist" keys dựa trên patterns:

💡 Ví Dụ Learned Bloom Filter

Trong web caching, URLs có pattern: /api/users/123/profile → likely exists, /api/users/99999999/profile → likely not exists (user ID range). Learned Bloom Filter có thể học distribution của valid URLs và giảm false positive rate từ 1% xuống 0.1% với cùng memory budget, hoặc giữ nguyên false positive rate nhưng dùng ít memory hơn 5x.

6. Giới Hạn Và Hướng Phát Triển

6.1 Limitations Của RM-Index Gốc

Không Hỗ Trợ Writes

Bất kỳ thay đổi dữ liệu nào đều yêu cầu retrain. Bài báo gốc acknowledge điều này nhưng không giải quyết.

Training Time Cao

Train RM-Index trên 200M records mất vài phút. B-Tree build từ sorted data mất vài giây. Không phù hợp cho dynamic indexing.

Worst Case Không Đảm Bảo

Nếu model prediction sai nhiều, linear scan range lớn → worst case tệ hơn B-Tree. max_error phụ thuộc vào training quality.

Distribution Drift

Nếu data distribution thay đổi theo thời gian (concept drift), model accuracy giảm. Cần periodic retraining.

7. Tác Động Lên Database Engineering

Bài báo RM-Index không chỉ đề xuất một kỹ thuật mới — nó mở ra một cách nhìn hoàn toàn mới về database internals:

⚡ Paradigm Shift: Data-Aware Index Structures

B-Tree được thiết kế để hoạt động tốt với bất kỳ data distribution nào — đây là strength nhưng cũng là weakness. Bằng cách "bake in" distribution knowledge vào index structure, learned indexes có thể vượt trội B-Tree trong specific scenarios. Đây là áp dụng của nguyên lý No Free Lunch theorem: không có algorithm nào tốt nhất cho tất cả cases. Khi bạn biết domain của mình, exploit knowledge đó.

7.1 Ứng Dụng Thực Tế Hiện Tại

Read-Only Analytical Workloads

Data warehouse với fact tables không thay đổi. Learned index có thể thay thế B-Tree index và tiết kiệm đáng kể memory → fit more data in RAM.

Embedded Systems / IoT

Memory-constrained environments. Learned index với 3 bytes/key vs B-Tree 100 bytes/key là difference quan trọng khi RAM chỉ có vài MB.

Time-Series Databases

Timestamps thường có gần-uniform distribution → linear model rất chính xác. InfluxDB và các TSDBs đang research learned indexes.

Spatial Indexes

Map coordinates với geographic distribution → ML model học được patterns của human settlement, coastlines, etc. Tốt hơn R-Tree cho specific regions.

7.2 Tại Sao Chưa Được Adopt Rộng Rãi?

⚠️ Thực Tế Sản Xuất Phức Tạp Hơn Lý Thuyết

Database production workloads không chỉ có reads. Mixed workloads, concurrent transactions, MVCC, crash recovery — tất cả phụ thuộc vào index structure có thể handle inserts/deletes một cách atomic. Cho đến khi learned indexes giải quyết được đầy đủ write semantics, concurrency control, và recovery mechanisms, adoption trong general-purpose databases sẽ còn hạn chế. Tuy nhiên, trong specialized systems (embedded, analytics, cold storage), learned indexes đang bắt đầu được sử dụng.

✅ Tầm Quan Trọng Lịch Sử

Dù adoption còn chậm, bài báo RM-Index có tầm quan trọng lịch sử: nó là bridge đầu tiên nối Machine Learning với Database Internals theo hướng cơ bản nhất — không phải "AI for query optimization" hay "ML for performance tuning", mà là "thay thế một cấu trúc dữ liệu cốt lõi bằng ML model". Điều này truyền cảm hứng cho một thế hệ nghiên cứu "Learned Database Components" — learned cardinality estimation, learned join ordering, learned buffer management — đang định hình tương lai của database systems.
