💾 InnoDB: Redo Log, Undo & Crash Recovery

Phan tich sau co che WAL, Rollback Segment, Purge va Crash Recovery trong MySQL InnoDB

1. Tong Quan: WAL va ACID

InnoDB dam bao ACID thong qua hai co che co ban: Redo Log (dam bao Durability va Atomicity khi commit) va Undo Log (dam bao Atomicity khi rollback va MVCC). Ca hai tuan theo nguyen tac WAL (Write-Ahead Logging): log phai duoc ghi truoc khi du lieu thay doi tren disk.

💡 Tai sao WAL?

Ghi sequential vao log file nhanh hon ghi random vao data files (vi du: HDD sequential ~100MB/s, random ~1MB/s). WAL cho phep commit nhanh bang cach chi can fsync log, de actual data pages duoc flush sau. Day la nen tang cua moi database engine hien dai.

2. Redo Log — Dam Bao Durability

2.1 Redo Log Block Structure

Redo log duoc to chuc thanh cac blocks 512 bytes (bang voi OS sector size de tranh partial write):

  • Log Block Header (12 bytes): block number, data length, first record offset, checkpoint number
  • Log Block Body: chua cac redo records
  • Log Block Trailer (4 bytes): checksum

2.2 LSN (Log Sequence Number)

LSN la monotonically increasing 8-byte number danh dau vi tri trong redo log stream. Moi byte cua redo log co mot LSN duy nhat. LSN duoc dung de:

  • Xac dinh Checkpoint position (diem bat dau Crash Recovery)
  • So sanh page LSN voi checkpoint LSN de quyet dinh can Redo hay khong
  • Kiem soat flush pressure (Modified age = current LSN - oldest dirty page LSN)

3. Rollback Segment va Undo Log

3.1 To Chuc Rollback Segment

InnoDB co toi da 128 Rollback Segments. Moi Rollback Segment co:

  • Rollback Segment Header Page: Chua 1024 Undo Slots, moi slot tro den mot Undo Log
  • Undo Log Header Page: Thong tin ve undo log cua mot transaction
  • Normal Undo Pages: Chua actual undo records

3.2 Insert Undo vs Update Undo

Insert Undo

  • Chi dung cho ROLLBACK (xoa record vua insert)
  • Transaction commit → co the thu hoi ngay
  • Khong can Purge thread xu ly

Update Undo

  • Dung cho ROLLBACK va MVCC
  • Transaction commit → KHONG thu hoi ngay
  • Phai doi Purge thread xu ly sau
  • Luu du lieu before-image day du

3.3 ROLLBACK_PTR — Lien Ket Undo Chain

Moi record co ROLLBACK_PTR (7 bytes) tro den undo record cua version truoc:

  • Bits [0-15]: Offset cua undo record trong Undo Page
  • Bits [16-47]: Page number cua Undo Page
  • Bits [48-54]: Rollback Segment ID (0-127)
  • Bit [55]: Undo type (0=Insert, 1=Update)

4. Purge — Thu Hoi Phien Ban Cu

4.1 Purge Flow

Purge thread chon transaction commit cu nhat trong tat ca Rollback Segments, duyet forward qua Update_Undo records, xoa cac records co DEL_BIT=1 khong con visible voi bat ky transaction nao:

1. Chon oldest committed transaction
2. Forward traverse Update_Undo records
3. Voi moi undo record: kiem tra visibility
4. Neu khong con ai thay: xoa clustered index record, xoa secondary index records
5. Thu hoi Undo Page neu day du

5.2 Doc Checkpoint LSN

Checkpoint LSN duoc luu tai 2 vi tri trong log group dau tien, file log dau tien:

  • LOG_CHECKPOINT_1 = offset 512 bytes (1 OS sector)
  • LOG_CHECKPOINT_2 = offset 1536 bytes (3 OS sectors)

Luu 2 ban du phong de phong truong hop ghi partial: InnoDB chon ban co Checkpoint LSN lon hon va hop le.

5.3 Redo Phase — Batch Apply

InnoDB doc redo log tu Checkpoint LSN den cuoi, ap dung theo co che Batch Apply:

  1. Doc redo records, nhom theo page (hash table: key = [space_id, page_no])
  2. Khi hash table day → duyet tung page, apply tat ca redo cua page do theo thu tu
  3. Red-Black Tree duy tri dirty pages theo oldest_modification de sort hieu qua

5.4 Undo Phase — Tai Tao Transactions

  1. Duyet tat ca Rollback Segment Header Pages
  2. Doc Undo Log Headers → khoi phuc cac transactions theo trang thai:
    • ACTIVE transactions: Rollback ngay
    • PREPARED transactions: Giao cho MySQL Server quyet dinh commit/rollback (XA recovery)
    • COMMITTED transactions: Chi can cho Purge thu hoi
  3. Rollback ACTIVE transactions → chay bat dong bo trong background thread

✓ Key Insight: Rollback Khong Chan Crash Recovery

InnoDB tao background thread de rollback cac active transactions, khong block viec hoan thanh crash recovery. He thong co the phuc vu requests moi trong khi rollback van dang chay. Day la dieu chinh khac so voi mot so database don gian hon.

6. Checkpoint Mechanism

6.1 Incremental Checkpoint (InnoDB)

InnoDB chi dung Incremental Checkpoint (khac voi Full Checkpoint qua cham). Quy tac:

  • Checkpoint age = current LSN - last_checkpoint_LSN
  • Modified age = current LSN - oldest dirty page LSN
  • Checkpoint age phai nho hon tong dung luong log files

6.2 Checkpoint Triggers

  • Vuot qua max_modified_age_async → async flush dirty pages
  • Vuot qua max_modified_age_sync → sync flush (block DML!)
  • Vuot qua max_checkpoint_age_async → async checkpoint
  • Vuot qua max_checkpoint_age → sync checkpoint (block DML!)

🚨 Loi "InnoDB: page cleaner: 1000ms intended loop..."

Log nay xuat hien khi page cleaner thread khong theo kip toc do ghi. Nguyen nhan: innodb_log_file_size qua nho, I/O throughput khong du, hoac too many dirty pages. Giai phap: tang innodb_log_file_size, tang innodb_io_capacity, hoac giam burst write workload.
