🌐 MySQL External XA & Distributed Transactions

Phan tich giao thuc XA, 2-Phase Commit va cac van de consistency trong distributed database

1. MySQL Internal XA — Nhat Quan InnoDB va Binlog

MySQL dung Internal XA de dam bao nhat quan giua InnoDB redo log va MySQL binlog. Binlog dong vai tro Transaction Coordinator:

InnoDB prepare → Binlog commit → InnoDB commit

💡 Tai sao can 2 buoc?

Neu chi commit InnoDB ma khong co Binlog: khi crash giua 2 buoc, Slave se khong nhan duoc transaction nay → master/slave inconsistent. XA dam bao ca 2 (InnoDB + Binlog) cung nhau hoac cung khong.

2. External XA — Distributed Transaction Across Databases

External XA cho phep mot giao dich trai qua nhieu MySQL instances. Application dong vai tro Transaction Coordinator.

-- XA flow:
XA START 'xid';
  -- thuc hien SQL operations
XA END 'xid';
XA PREPARE 'xid';     -- Phase 1: Tat ca participants sẵn sàng
XA COMMIT 'xid';      -- Phase 2: Commit tat ca (hoac XA ROLLBACK)

-- Recover sau crash:
XA RECOVER;           -- Liet ke cac prepared XA transactions

3. XA Crash Recovery: 5 Tinh Huong

Tinh huongTrang thaiHanh dong
1Mot so nodes chua prepare xongRollback cac nodes da prepare
2Tat ca prepare, chua commitCo the commit (nen) hoac rollback
3Tat ca prepare, mot so da commitCommit cac nodes con trong prepare state
4Tat ca da commitKhong can xu ly
5Chua ghi prepare log naoTat ca tu dong rollback

⚠️ Tinh huong 2 vs 3: Van De Kho Phan Biet

Chi nhin vao so luong prepared nodes khong phan biet duoc tình huong 1 (rollback) va 3 (commit). Application PHAI ghi log rieng sau khi tat ca nodes prepare thanh cong de biet can commit hay rollback.

4. Van De Nghiem Trong Cua MySQL External XA

🚨 Van De 1: Master/Slave Inconsistency

MySQL Binlog khong ghi prepare log cho XA transactions (chi ghi commit). Trong tinh huong 2 (prepare xong, chua commit, crash): sau recovery neu chon commit → InnoDB commit nhung binlog khong co entry → Slave khong nhan duoc → Master/Slave KHONG NHAT QUAN. Day la bug ton tai trong MySQL 5.5.16 (da duoc xac nhan).

🚨 Van De 2: Partial Commit Across Nodes

Neu rollback tat ca prepared transactions (de tranh van de 1), tinh huong 3 se bi sai: mot so nodes da commit, mot so bi rollback → cung mot distributed transaction co ket qua khac nhau tren cac nodes!

💡 Bug trong MySQL 5.1.49

xa commit 'xid' bi convert thanh xa rollback do bug trong xid_cache_insert (thieu dong xs->rm_error = 0). Da fix trong MySQL 5.5.16+. Nen luon dung MySQL 5.5.16+ khi dung External XA.

5. Giai Phap: Binlog Cung Tham Gia XA

Giai phap chinh thong: sua doi binlog module de phan biet Internal XA va External XA. Voi External XA, binlog phai ghi BOTH prepare va commit log (giu vai tro Resource Manager, khong phai Transaction Coordinator nua).

Cac cong cu proxy ho tro XA: Amoeba, DDB (NetEase), TDDL (Taobao), Cobar (B2B Alibaba).

6. Group Commit — Toi Uu Throughput Commit

Group Commit (MySQL 5.6+, MariaDB 5.5.19+) cho phep nhieu transactions cung flush binlog 1 lan, giam fsync() calls:

  • Flush stage: Ghi binlog vao buffer
  • Sync stage: fsync() cho ca group
  • Commit stage: InnoDB commit cho ca group

✓ Crash Recovery Voi Group Commit

Voi Group Commit, khi binlog file switch, phai dam bao prepared_xids = 0 (tat ca prepared transactions trong binlog group da hoan thanh). InnoDB redo log ghi (binlog_file, binlog_pos) de crash recovery co the bat dau tu dung vi tri.
