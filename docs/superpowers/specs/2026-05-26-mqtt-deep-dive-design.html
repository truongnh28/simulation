3. Section Content Spec

s1 MQTT là gì

Mở đầu: MQTT (Message Queuing Telemetry Transport) được thiết kế năm 1999 bởi Andy Stanford-Clark (IBM) và Arlen Nipper cho pipeline monitoring qua vệ tinh — nơi bandwidth cực hạn chế và connection không ổn định. Đây là lý do MQTT tối ưu cho IoT hơn HTTP.

Publish/subscribe model: Publisher gửi message đến topic trên broker, không biết subscriber là ai. Subscriber đăng ký topic, không biết publisher là ai. Broker là intermediary duy nhất — decouples producer và consumer hoàn toàn.

2 mini-scenarios mở đầu:

  • IoT sensor network: 1000 temperature sensors gửi home/{room}/temperature mỗi 10 giây với QoS 0. Dashboard subscribe home/# nhận tất cả. Nếu mất kết nối → broker giữ session, gửi lại khi reconnect.
  • Drone fleet: Drone publish drone/001/telemetry (GPS/battery/altitude) mỗi 200ms QoS 0. Ground station subscribe và hiện real-time. LWT publish drone/001/status = "offline" tự động khi drone mất kết nối. Command channel drone/001/command QoS 1 (ít nhất 1 lần đến).

So sánh với HTTP/WebSocket:

s2 Fixed Header & Packet Types

Fixed header structure: Mọi MQTT packet đều bắt đầu bằng 2–5 bytes fixed header:

  • Byte 1: bits 7–4 = packet type (4 bits, 16 values), bits 3–0 = flags (4 bits, ý nghĩa tùy packet type)
  • Byte 2+: Remaining Length — số bytes còn lại của packet (variable header + payload). Dùng variable-length encoding (VLE): mỗi byte dùng 7 bits cho value, bit MSB = 1 nếu còn byte tiếp theo. Tối đa 4 bytes → max packet size = 256 MB.

VLE encoding ví dụ: Value 321 = 0xC1 0x02 (bit 7 set trong byte đầu = "còn tiếp", 0x41 | 0x80 = 0xC1; byte 2 = 0x02).

Flags nibble: PUBLISH dùng cả 4 bits (DUP=bit3, QoS=bits2-1, RETAIN=bit0). Các packet khác có flags cố định (0000 hoặc 0010).

s3 CONNECT Packet

Wire format byte-by-byte — đây là packet quan trọng nhất, thiết lập toàn bộ session parameters:

Fixed header: 2 bytes: 0x10 (type=1, flags=0) + remaining length (VLE).

Variable header (10 bytes cố định trong MQTT 3.1.1):

  • Bytes 0–5: Protocol Name — 2 bytes length (0x00 0x04) + "MQTT" (4 bytes UTF-8)
  • Byte 6: Protocol Level — 0x04 cho MQTT 3.1.1, 0x05 cho MQTT 5.0
  • Byte 7: Connect Flags — 8 bits mỗi bit là 1 feature flag
  • Bytes 8–9: Keep Alive — 2 bytes big-endian, seconds (0 = disable)

Connect Flags byte (byte 7) breakdown:

  • Bit 7: Username Flag
  • Bit 6: Password Flag
  • Bit 5: Will Retain
  • Bits 4–3: Will QoS (00/01/10)
  • Bit 2: Will Flag
  • Bit 1: Clean Session (3.1.1) / Clean Start (5.0)
  • Bit 0: Reserved (phải = 0)

Payload (variable length): ClientID (bắt buộc, UTF-8) → Will Topic (nếu Will Flag=1) → Will Message → Username (nếu flag=1) → Password. Mỗi field: 2 bytes length prefix + data.

SVG: CONNECT packet byte layout annotated.

Python example:

import paho.mqtt.client as mqtt

client = mqtt.Client(client_id="drone-001", clean_session=False)
client.username_pw_set("user", "secret")

# Last Will — gửi tự động nếu connection bị drop
client.will_set("drone/001/status", payload="offline", qos=1, retain=True)

client.connect("broker.emqx.io", port=1883, keepalive=60)
client.loop_start()

s4 Topics & Wildcards

Topic structure: UTF-8 string, phân cấp bằng /. Case-sensitive. Không có leading/trailing slash convention — nhưng tránh leading slash vì tạo ra empty string level đầu tiên.

Best practice naming: {context}/{deviceId}/{metric} — ví dụ drone/001/telemetry, home/kitchen/temperature.

Wildcards (chỉ dùng trong SUBSCRIBE, không dùng trong PUBLISH):

  • + (single-level): thay thế đúng 1 level. drone/+/telemetry match drone/001/telemetry, drone/002/telemetry nhưng không match drone/001/sensor/gps
  • # (multi-level): thay thế 0 hoặc nhiều levels, phải ở cuối. drone/# match tất cả topics bắt đầu bằng drone/

$SYS topics: Namespace dành riêng của broker. $SYS/broker/clients/connected, $SYS/broker/messages/received. Subscribe # không match $SYS — phải subscribe explicit.

SVG: Topic wildcard tree diagram.

Python example — multi-drone monitoring:

def on_message(client, userdata, msg):
    # msg.topic = "drone/003/telemetry"
    parts = msg.topic.split("/")
    drone_id = parts[1]      # "003"
    metric   = parts[2]      # "telemetry"
    payload  = json.loads(msg.payload)
    print(f"Drone {drone_id}: lat={payload['lat']}, battery={payload['battery']}%")

client.subscribe("drone/+/telemetry", qos=0)   # tất cả drones
client.subscribe("drone/+/status",    qos=1)   # LWT status
client.on_message = on_message

s5 PUBLISH Packet

Fixed header flags nibble cho PUBLISH:

  • DUP (bit 3): = 1 khi retransmitting QoS 1/2 packet. Broker/client không được dùng DUP để detect duplicates — chỉ mang tính informational.
  • QoS (bits 2–1): 00=QoS0, 01=QoS1, 10=QoS2, 11=reserved (không dùng)
  • RETAIN (bit 0): = 1 → broker lưu message này làm "last known value" cho topic

Variable header: Topic Name (2 bytes length + UTF-8 string) + Packet Identifier (2 bytes, chỉ có khi QoS > 0).

Payload: Binary data, không có length prefix — length được tính từ remaining length. Payload có thể empty (0 bytes) — dùng để clear retained message.

MQTT 5.0 properties trong variable header: Thêm Properties Length (VLE) + properties list trước payload.

Python example — drone telemetry publisher:

import json, time, math, paho.mqtt.client as mqtt

client = mqtt.Client("drone-publisher")
client.connect("broker.emqx.io", 1883)
client.loop_start()

flight_time = 0
while True:
    telemetry = {
        "lat":     10.7769 + math.sin(flight_time * 0.1) * 0.01,
        "lng":     106.7009 + math.cos(flight_time * 0.1) * 0.01,
        "alt":     50 + math.sin(flight_time * 0.05) * 10,
        "battery": max(0, 100 - flight_time * 0.5),
        "ts":      int(time.time() * 1000)
    }
    client.publish("drone/001/telemetry", json.dumps(telemetry), qos=0)
    flight_time += 1
    time.sleep(0.2)

s6 QoS 0 — At-most-once

Mechanics: Publisher gửi PUBLISH, không đợi ACK. Broker nhận xong forward ngay cho subscribers, không lưu. Nếu connection drop ở bất kỳ điểm nào → message mất, không retry.

Wire: Chỉ 1 PUBLISH packet. Không có Packet Identifier trong variable header. Fixed header flags = 0x30 (type=3, QoS=00).

Use cases: Sensor telemetry (temperature, GPS) gửi liên tục — mất 1 reading không sao; logging metrics; real-time dashboards nơi stale data tệ hơn missing data.

Drone context: drone/001/telemetry — gửi 5 lần/giây, mất vài packet không ảnh hưởng display.

s7 QoS 1 — At-least-once

Mechanics: Publisher gửi PUBLISH (với Packet Identifier), chờ PUBACK. Nếu không nhận PUBACK trong timeout → retransmit với DUP=1. Kết quả: subscriber có thể nhận duplicate.

Packet Identifier: 2 bytes, unique per in-flight QoS 1/2 message. Range 1–65535. Client tự quản lý, reuse sau khi nhận PUBACK.

Broker behavior: Forward PUBLISH đến tất cả matching subscribers với QoS ≤ subscribed QoS. Nếu subscriber offline + persistent session → broker queue message, gửi khi reconnect.

Use cases: Command đến drone (waypoint, return-home), notifications, alerts — message phải đến ít nhất 1 lần, duplicate acceptable.

Python example:

def send_command(client, drone_id, command):
    payload = json.dumps({"cmd": command, "ts": time.time()})
    result = client.publish(f"drone/{drone_id}/command", payload, qos=1)
    result.wait_for_publish()   # block until broker ACK'd
    print(f"Command sent to {drone_id}: {command}")

send_command(client, "001", "return_home")

s8 QoS 2 — Exactly-once

4-step handshake:

  1. PUBLISH (sender → receiver): gửi message, lưu vào "sent" store với packet ID
  2. PUBREC (receiver → sender): "tôi đã nhận, nhưng chưa deliver" — receiver lưu packet ID
  3. PUBREL (sender → receiver): "OK, bạn có thể deliver" — sender có thể xóa message khỏi store
  4. PUBCOMP (receiver → sender): "đã deliver xong" — receiver xóa packet ID

Guarantee mechanism: Bước 1-2 có thể retry (PUBLISH với DUP=1 nếu không nhận PUBREC). Bước 3-4 có thể retry (PUBREL nếu không nhận PUBCOMP). Receiver chỉ deliver một lần vì lưu packet ID — nhận PUBLISH lần 2 với cùng ID → discard (đã deliver rồi).

Cost: 4 packets, 2 round-trips, state cả 2 phía. Dùng khi: financial transactions, critical alerts, firmware OTA commands.

SVG: QoS 0/1/2 state machine 3-in-1 diagram.

Python example:

client.publish("drone/001/firmware/update",
               payload=firmware_metadata_json,
               qos=2)   # exactly-once — firmware command không duplicate được

s9 Retained Messages & LWT

Retained Messages: PUBLISH với RETAIN=1 → broker lưu message này cho topic. Subscriber mới kết nối → nhận ngay retained message (không cần chờ publisher gửi lần tới). Chỉ 1 retained message/topic tồn tại cùng lúc — message mới overwrite. Clear bằng cách publish empty payload với RETAIN=1.

Use case: Device status ("online"), last known sensor reading, configuration value. Khi dashboard khởi động → nhận ngay giá trị hiện tại của tất cả sensors mà không cần đợi.

Last Will and Testament (LWT): Client khai báo trong CONNECT: nếu connection bị drop bất thường (không gửi DISCONNECT), broker sẽ publish will message thay cho client. Will không được gửi nếu client disconnect bình thường (gửi DISCONNECT packet).

LWT fields trong CONNECT payload: Will Topic + Will Message + Will QoS + Will Retain flag.

MQTT 5.0 Will Delay Interval: Broker chờ N giây trước khi publish will — cho phép client reconnect kịp (short network blip không trigger LWT).

Drone birth/death pattern:

def setup_drone_client(drone_id: str) -> mqtt.Client:
    client = mqtt.Client(drone_id, clean_session=False)

    # LWT — broker gửi tự động nếu drone mất kết nối
    client.will_set(
        topic=f"drone/{drone_id}/status",
        payload=json.dumps({"status": "offline", "ts": time.time()}),
        qos=1,
        retain=True
    )
    client.on_connect = lambda c, u, f, rc: (
        # Birth message — gửi khi connect thành công
        c.publish(f"drone/{drone_id}/status",
                  json.dumps({"status": "online", "ts": time.time()}),
                  qos=1, retain=True)
    )
    return client

s10 Persistent Sessions

Clean Session (3.1.1) / Clean Start (5.0):

  • clean_session=True: Broker xóa toàn bộ session state khi client disconnect. Reconnect = new session. Subscriptions mất, queued messages mất.
  • clean_session=False: Broker lưu session state. Reconnect → broker trả lại: subscriptions, QoS 1/2 messages đang chờ, in-flight QoS 2 state. CONNACK trả về Session Present flag = 1 nếu session đã tồn tại.

Session state broker lưu:

  • Subscription list (topic filters + QoS)
  • QoS 1 messages đang chờ deliver (offline queue)
  • QoS 2 messages đang trong handshake (PUBREC received, chờ PUBREL)

MQTT 5.0 Session Expiry Interval: Property trong CONNECT/DISCONNECT — broker xóa session sau N giây offline (thay vì giữ mãi mãi). 0 = xóa khi disconnect; 0xFFFFFFFF = giữ mãi.

Client Takeover: Broker cho phép 2 clients dùng cùng clientID không? → Broker terminate kết nối cũ, accept kết nối mới. Tránh bằng unique clientID per device.

Python example — reconnect với persistent session:

client = mqtt.Client("drone-001", clean_session=False)

def on_connect(client, userdata, flags, rc):
    if flags.get("session present"):
        print("Session restored — broker có queued messages")
    else:
        print("New session — re-subscribe")
        client.subscribe([
            ("drone/001/command", 1),
            ("drone/001/config",  1),
        ])

client.on_connect = on_connect

s11 SUBSCRIBE & SUBACK

SUBSCRIBE packet: Fixed header 0x82 (type=8, flags=0010 — flags cố định). Variable header: Packet Identifier (2 bytes). Payload: danh sách topic filters, mỗi filter = 2 bytes length + UTF-8 string + 1 byte options.

QoS negotiation: Client request QoS X, broker có thể grant QoS ≤ X. SUBACK trả về list return codes (1 byte/filter): 0x00=QoS0, 0x01=QoS1, 0x02=QoS2, 0x80=Failure.

MQTT 5.0 Subscription Options (1 byte):

  • No-local (bit 2): = 1 → broker không gửi message từ chính client đó về cho client (tránh echo)
  • Retain-as-published (bit 3): = 1 → broker giữ nguyên RETAIN flag khi forward (không strip)
  • Retain Handling (bits 5–4): 0=gửi retained khi subscribe, 1=chỉ gửi nếu subscription mới, 2=không gửi retained

Python example:

def on_subscribe(client, userdata, mid, granted_qos):
    print(f"Subscribed — granted QoS: {granted_qos}")
    # granted_qos = (1,) nếu broker chấp nhận QoS 1

client.on_subscribe = on_subscribe
client.subscribe([
    ("drone/+/telemetry", 0),   # high-frequency, QoS 0 OK
    ("drone/+/status",    1),   # status update, QoS 1
    ("drone/+/command",   1),   # command echo, QoS 1
])

s12 MQTT 5.0 Core Features

MQTT 5.0 (2019) giải quyết những hạn chế lớn của 3.1.1 bằng cách thêm Properties system vào hầu hết packets.

Reason Codes: 3.1.1 CONNACK chỉ có 6 return codes; 5.0 thêm reason code đầy đủ cho mọi packet (PUBACK, SUBACK, DISCONNECT). Ví dụ: DISCONNECT reason code 0x8D = "Keep Alive timeout", 0x9C = "Use Another Server".

User Properties: UTF-8 key-value pairs trong bất kỳ packet nào. Tương đương HTTP headers cho MQTT. Dùng cho: routing metadata, tracing IDs, device firmware version.

Message Expiry Interval: PUBLISH property — broker drop message sau N giây nếu chưa deliver. Ngăn stale commands chạy trên device sau khi reconnect.

Topic Aliases: Map topic string → integer (1–N). Sau khi map một lần, gửi integer thay chuỗi dài. drone/fleet/001/sensors/gps/telemetry/v2 → alias 1. Tiết kiệm bandwidth đáng kể.

Content Type: UTF-8 string mô tả payload format — application/json, application/cbor.

Response Topic + Correlation Data: Request/response pattern: publisher thêm Response Topic và Correlation Data vào PUBLISH. Subscriber xử lý xong → publish response về Response Topic kèm Correlation Data để match request.

Flow Control (Receive Maximum): CONNECT property — client báo broker số lượng max in-flight QoS 1/2 messages có thể handle đồng thời. Tránh overwhelm client yếu.

s13 Shared Subscriptions & Enhanced Auth

Shared Subscriptions (MQTT 5.0, nhiều broker 3.1.1 cũng hỗ trợ): Syntax: $share/{ShareName}/{TopicFilter}. Nhiều clients subscribe cùng group → broker load-balance messages (round-robin hoặc random). Không phải fan-out (mỗi message chỉ đến 1 subscriber trong group).

Use case: 3 ground stations subscribe $share/groundcrew/drone/+/telemetry → mỗi telemetry message chỉ đến 1 ground station. Scale horizontally bằng cách thêm subscriber vào group.

Enhanced Authentication (AUTH packet — MQTT 5.0): Cho phép multi-step auth flow (challenge-response) thay vì chỉ username/password một lần trong CONNECT. Flow SCRAM: CONNECT (auth method="SCRAM-SHA-256", auth data=client-first) → AUTH (auth data=server-first) → AUTH (auth data=client-final) → CONNACK.

Python example — shared subscription:

import paho.mqtt.client as mqtt

# Ground station 1
gs1 = mqtt.Client("ground-station-1")
gs1.connect("broker.emqx.io", 1883)
gs1.subscribe("$share/groundcrew/drone/+/telemetry", qos=1)

# Ground station 2 (cùng group, load-balanced)
gs2 = mqtt.Client("ground-station-2")
gs2.connect("broker.emqx.io", 1883)
gs2.subscribe("$share/groundcrew/drone/+/telemetry", qos=1)

# Mỗi telemetry message chỉ đến gs1 HOẶC gs2, không phải cả 2

s14 Security

Transport Security — TLS: Port 8883 (MQTTS) = MQTT over TLS. Port 8884 = MQTT over WSS. Cấu hình paho-mqtt:

import ssl
client.tls_set(
    ca_certs="/path/to/ca.crt",
    certfile="/path/to/client.crt",   # cho mTLS
    keyfile="/path/to/client.key",    # cho mTLS
    cert_reqs=ssl.CERT_REQUIRED,
    tls_version=ssl.PROTOCOL_TLS_CLIENT
)
client.connect("broker.example.com", port=8883)

mTLS cho device identity: Mỗi drone có certificate riêng (signed bởi private CA). Broker verify certificate thay vì username/password — phù hợp IoT vì không cần secret management trên device.

Username/Password: Gửi trong CONNECT payload (cleartext trên TCP → bắt buộc dùng TLS). Paho: client.username_pw_set("user", "pass").

ACL (Access Control List): Broker-level authorization — ví dụ Mosquitto ACL file:

user drone-001
topic write drone/001/#
topic read  drone/001/command

user dashboard
topic read drone/+/telemetry
topic read drone/+/status

Các attack vectors cần biết: Brute force clientID takeover (dùng random suffix), retained message poisoning (ACL trên retained topics), subscription storm (limit sub rate per client), payload injection (validate JSON schema trên broker side).

Pattern 2 — Command/Control (QoS 1):

# ground_station.py
import json, time, paho.mqtt.client as mqtt

BROKER = "broker.emqx.io"
GS_ID  = "ground-station-001"

def on_message(client, userdata, msg):
    topic = msg.topic
    data  = json.loads(msg.payload)

    if "/telemetry" in topic:
        drone_id = topic.split("/")[1]
        print(f"[{drone_id}] lat={data['lat']:.4f} lng={data['lng']:.4f} "
              f"alt={data['alt_m']}m bat={data['bat_pct']}%")

    elif "/status" in topic:
        drone_id = topic.split("/")[1]
        print(f"[{drone_id}] STATUS: {data['status']}")

client = mqtt.Client(GS_ID)
client.on_message = on_message
client.connect(BROKER, 1883)

client.subscribe([
    ("drone/+/telemetry", 0),
    ("drone/+/status",    1),
])

# Gửi lệnh đến drone
def send_command(drone_id: str, command: str, params: dict = {}):
    payload = json.dumps({"cmd": command, "params": params,
                          "ts": int(time.time() * 1000)})
    result = client.publish(f"drone/{drone_id}/command", payload, qos=1)
    result.wait_for_publish()
    print(f"Command '{command}' sent to {drone_id}")

client.loop_start()
time.sleep(2)

s16 MQTT over WebSocket

Tại sao cần MQTT-WS: Browser không có raw TCP socket API → không kết nối MQTT trực tiếp. MQTT over WebSocket = MQTT frames gói trong WebSocket binary frames.

WebSocket Upgrade: Client gửi HTTP Upgrade với Sec-WebSocket-Protocol: mqtt. Sau khi upgrade → gửi CONNECT packet như bình thường, chỉ transport layer là WS thay vì TCP.

Ports: 8083 = MQTT over WS (plain), 8084 = MQTT over WSS (TLS). Mosquitto config: listener 8083 / protocol websockets.

paho-mqtt WS transport:

import paho.mqtt.client as mqtt

client = mqtt.Client(transport="websockets")
client.tls_set()   # cho WSS (port 8084)
client.connect("broker.emqx.io", port=8084)

# Hoặc plain WS:
client = mqtt.Client(transport="websockets")
client.connect("broker.emqx.io", port=8083)

s18 Production & Python Patterns

paho-mqtt API patterns:

import paho.mqtt.client as mqtt
import json, threading, time

class MQTTService:
    def __init__(self, broker: str, port: int, client_id: str):
        self._client = mqtt.Client(client_id, clean_session=False)
        self._client.on_connect    = self._on_connect
        self._client.on_disconnect = self._on_disconnect
        self._client.on_message    = self._on_message
        self._handlers = {}
        self._broker = broker
        self._port   = port

    def add_handler(self, topic_pattern: str, fn):
        self._handlers[topic_pattern] = fn
        self._client.message_callback_add(topic_pattern, fn)

    def _on_connect(self, client, userdata, flags, rc):
        if rc == 0:
            print("Connected")
            for pattern in self._handlers:
                client.subscribe(pattern, qos=1)
        else:
            print(f"Connect failed rc={rc}")

    def _on_disconnect(self, client, userdata, rc):
        print(f"Disconnected rc={rc} — auto-reconnect...")

    def _on_message(self, client, userdata, msg):
        print(f"Unhandled: {msg.topic}")

    def start(self):
        self._client.connect(self._broker, self._port,
                             keepalive=60)
        self._client.reconnect_delay_set(min_delay=1, max_delay=30)
        self._client.loop_start()   # non-blocking background thread

    def publish(self, topic: str, payload, qos: int = 0, retain: bool = False):
        return self._client.publish(topic, json.dumps(payload), qos=qos, retain=retain)

Capacity planning rules of thumb:

  • Mosquitto: ~1 MB RAM / 1000 connections (với default buffer sizes)
  • QoS 0: negligible broker storage; QoS 1/2 offline queues: giới hạn bằng max_queued_messages
  • Persistent sessions: cần disk cho queued messages khi broker restart
  • Topic fanout N subscribers × M messages/s = bottleneck → dùng shared subscriptions
